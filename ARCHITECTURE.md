# Architecture
Local-first modular React application. Proposed: Vite, TypeScript strict, Tailwind, accessible UI primitives, IndexedDB via Dexie when persistence is implemented. App composes features; features depend on domain, shared UI and explicit persistence interfaces, not other features. Domain has no UI or infrastructure dependencies. Infrastructure implements domain ports. Introduce folders only when needed. Use versioned schemas for imports and migrations. Deployment uses Vercel; GitHub Actions validates the application. No backend or authentication in MVP. Test domain with Vitest and journeys with Playwright; add lint and CI when scaffolding application. Catalog loading is shared infrastructure; image sampling stays local in the browser.

Recipe writes share one read–update operation. Browsers with Web Locks serialize that operation across tabs. The Atelier listens for storage changes to refresh saved recipes and comparisons. The mixer, search, Cel shading, Academy and Atelier load on their first visit. Tool URLs support browser history and reload. Visited tools retain working state in the current session. Cel shading loads its artwork on demand. Goku masks are stored as region and tone attributes on the SVG paths. The build combines the source catalog files into one data request. Catalog consumers share the same cached data and recover together after a retry. Recipes record optional primer, coat count and user-reported application tests, alongside catalog range and code, with legacy names supported by the dilution lookup.

The production build emits HTML for eight public entry points, with links and page metadata available before React runs. It also accepts legacy hash entry points. Set `SITE_URL` to the final public HTTPS origin to generate canonical URLs and the sitemap. Vercel production builds can fall back to `VERCEL_PROJECT_PRODUCTION_URL`. Vercel preview builds are marked `noindex` and omit the sitemap. Submit the generated `/sitemap.xml` to Google Search Console after deploying on the final domain.
The CI workflow audits the compiled Home, Academy and Mixer routes with Lighthouse. Playwright checks axe rules in both themes, including the save dialog. To run the equivalent Lighthouse audit locally, use Node 22.19 or newer, build the app and set CHROME_PATH to a Chrome or Playwright Chromium executable before running npm run test:lighthouse.
